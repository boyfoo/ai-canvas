# 组件使用手册

本手册用于在当前工程内直接查找和复用组件。盘点日期：2026-11-04。范围覆盖 src/components 与 src/pages/canvas 中公开导出的 React 组件，包括默认导出的路由页。

当前共 **223 个组件实现文件、274 个公开组件导出**；同一文件的多个组件合并为一行。族级 index.ts 的转导出不重复计数；hooks、类型、Context 对象、常量、工具函数及文件私有组件不计入组件目录。

## 先选哪一层

| 需求 | 优先入口 |
| --- | --- |
| 普通图标按钮、工具激活态、复选、开关、单选 | ui/base 对应组件族 |
| 产品弹窗、侧栏、空态、提示 | ui/product 对应组件族 |
| 图片缓存显示、完整视频播放、中央播放图标 | CachedResourceImage、VideoPlayer、VideoPlayButton |
| 轻量的媒体预览、左右切换、悬浮工具条 | canvas/media-preview 四组件 |
| 画布节点媒体或 @引用预览 | CanvasMediaVersionPreview、CanvasReferencePreview |
| 当前节点历史结果选择与恢复 | CanvasVersionCompareModal |
| 整张画布的文档保存版本 | pages/canvas 下的 CanvasVersionHistory、CanvasVersionPreview |
| 完整项目页面、助手、导演或时间线 | 对应业务组件；沿用项目页已有宿主与动作 |

UI 分层遵循 [组件层说明](../src/components/ui/README.md)：base 是原语及基础控件，product 是跨页面模式件；特效文件实际仍在 ui/aceternity。**当前没有 ui/fx 或 ui/application 目录**，不把规划路径当作可用导入路径。

ui/base/kbd 与 ui/product/settings-row 目录目前为空。Kbd、ButtonGroup、NodeTypeBadge、ComboBox、loading-state、section-card、property-row 没有可导入实现；需要相应能力时先查看现有组件和依赖，不能直接按这些规划名导入。

## 样式与宿主前提

1. **在已有应用内复用**：入口已加载 [全局样式与主题 token](../src/styles/globals.css)，并挂载 [AppProviders](../src/components/layout/app-providers.tsx)。不要在每个小组件外重复创建应用 Provider。
2. **应用级 Provider**：AppProviders 提供 AntD ConfigProvider/App、React Query、明暗外观和浏览器工作区初始化。使用 App.useApp 的通知/确认操作、查询及业务组件应处于该宿主内。带路由行为的页面还需要现有 Router。
3. **画布业务上下文**：CanvasNode 与部分内容组件依赖 CanvasNodeActionContext、CanvasNodeGraphContext；浮层使用 CanvasOverlayLayerProvider；编辑器模块使用 EditorStoreProvider。装配方式分别参考 [画布项目页](../src/pages/canvas/project.tsx)、[节点动作上下文](../src/components/canvas/canvas-node-action-context.ts)、[编辑器上下文](../src/components/editor/editor-context.tsx)。这些组件公开导出，不等于只传 children 就能独立运行。
4. **受控数据与动作**：节点组件使用真实 CanvasNodeData、配置快照及相应更新回调；项目页组件还接收项目、选区、视口、任务或素材状态。不要用空函数替代保存、恢复或生成成功逻辑。
5. **素材与宿主服务**：显示浏览器 URL 与 storageKey 是两条真实来源。CachedResourceImage 和资源播放 hook 负责已有缓存及资源解析；不要因为“显示”而新增 fetch→Blob 或自动生成。深度处理、转写、模型生成、工作流等业务能力仍需其已有配置和服务。
6. **导入方式**：Vite/TypeScript 的 @/ 映射到 src。UI 族优先使用表中族级深路径；其它组件从实际模块导入。源码链接可点击查看实时 Props，不复制实现到新文件。Props 没有公开导出时，可用 React.ComponentProps<typeof 组件> 推导。
7. **主题与图标**：基础 UI 消费 CSS token；画布外观沿用 useActiveTheme/canvasThemes。IconButton、EmptyState 接收 Lucide 图标组件引用；ToolButton、CanvasPreviewButton 的 icon 接收 ReactNode，按各自接口传入。

这些前提是组件现有依赖说明；本手册没有新增后端、配置层或组件副本。

## 常用组件复制示例

以下示例用于当前工程已有应用宿主内。示例只展示 UI、浏览器已有静态图片或调用方传入的媒体地址，不上传文件或发起模型生成。

### 基础控件、提示与产品弹窗

~~~tsx
import { useState } from "react";
import { Settings2, Layers } from "lucide-react";

import { IconButton, ToolButton } from "@/components/ui/base/buttons";
import { SegmentedControl } from "@/components/ui/base/segmented-control";
import { Switch } from "@/components/ui/base/switch";
import { StatusBadge } from "@/components/ui/base/badges";
import { AppModal } from "@/components/ui/product/app-modal";
import { Callout } from "@/components/ui/product/callout";

export function CommonControlsExample() {
    const [open, setOpen] = useState(false);
    const [enabled, setEnabled] = useState(true);
    const [mode, setMode] = useState<"image" | "video">("image");

    return (
        <div className="flex flex-wrap items-center gap-2">
            <IconButton
                icon={Settings2}
                aria-label="打开设置"
                onClick={() => setOpen(true)}
            />
            <ToolButton
                icon={<Layers />}
                label="图层"
                active={enabled}
                onClick={() => setEnabled((value) => !value)}
            />
            <SegmentedControl
                ariaLabel="媒体类型"
                value={mode}
                onChange={setMode}
                options={[
                    { value: "image", label: "图片" },
                    { value: "video", label: "视频" },
                ]}
            />
            <Switch checked={enabled} onChange={setEnabled} aria-label="显示图层" />
            <StatusBadge tone="success" label="已保存" />
            <AppModal open={open} title="设置" onCancel={() => setOpen(false)} footer={null}>
                <Callout tone="info" title="当前选择">
                    {mode === "image" ? "图片" : "视频"}
                </Callout>
            </AppModal>
        </div>
    );
}
~~~

IconButton 使用 aria-label 给纯图标命名；ToolButton 的 active 是持久状态，浮层开关可使用其 expands 属性表达。不要把它们与 CanvasPreviewButton 的固定位置、仅亮度反馈混为一种动效。

### 缓存图片与视频播放器

~~~tsx
import { CachedResourceImage } from "@/components/cached-resource-image";
import { VideoPlayer } from "@/components/video-player";

export function CachedImageExample({ storageKey }: { storageKey?: string }) {
    return (
        <div className="h-40 w-64 [&>.cached-resource-image-shell]:block [&>.cached-resource-image-shell]:size-full">
            <CachedResourceImage
                storageKey={storageKey}
                src="/lighting-presets/rembrandt.png"
                alt="布光预览"
                className="size-full object-cover"
                fallback={<span>图片暂不可用</span>}
                loading="lazy"
            />
        </div>
    );
}

export function VideoExample({ src }: { src: string }) {
    return (
        <VideoPlayer
            src={src}
            title="视频预览"
            autoPlay={false}
            compactControls
            dataCanvasNoZoom
        />
    );
}
~~~

storageKey 必须来自已有真实素材；没有存储键时可只给 src。存储图片可能有包装 span，填充布局要同时设置包装层尺寸。VideoPlayer 接收可播放 src，不负责把服务商 asset:// 变成浏览器地址；其 CSS 已由组件导入，暂停中央按钮复用 VideoPlayButton。

CanvasImagePreview 用于图片放大和缩放拖动；CanvasReferencePreview 用于真实 CanvasResourceReference 的统一预览；CanvasMediaVersionPreview 用于节点历史首帧/封面，不是完整播放器。

## 透明媒体预览组件族

统一从 [canvas/media-preview](../src/components/canvas/media-preview/index.ts) 导入。四个组件均不依赖 CanvasNodeData，不自行选择版本、更新节点、上传、生成或下载。按钮与工具条自行消费当前主题；布局组件没有 theme 参数。

| 组件 | 必填 Props | 可选 Props与职责 |
| --- | --- | --- |
| CanvasMediaLightbox | open、title、onClose、children | 透明 AppModal 外壳，负责遮罩、Esc、焦点与关闭后销毁。title 用于可访问名称。 |
| CanvasMediaPreviewFrame | width、height、onClose、children | label、onPrevious、onNext、toolbar；按自然比例布局，缺少相邻回调时禁用箭头，不循环。 |
| CanvasPreviewToolbar | label、children | className；Dock 主题与工具条可访问分组。 |
| CanvasPreviewButton | label | icon、children、disabled、onClick、title、className、style、floating；children 未传时为圆形按钮，floating 默认 false。 |

四个对应 Props 类型也从同一个 index.ts 导出。floating 仅提供悬浮按钮外观；按钮统一禁止位移缩放，仅保留启用状态下的轻微亮度反馈。底部条不应跟随悬浮按钮另改底色。

### 完整可复制的本地图片浏览示例

下面两个函数和图片数组可直接放在同一 TSX 文件。图片已存在于 public/lighting-presets，不使用外部服务。**索引与图片自然尺寸状态放在 Lightbox 的子组件中**，关闭动画结束销毁后，再次打开从第一张开始。业务状态若放在外部父组件，Lightbox 无法替调用方重置它。

~~~tsx
import { useState } from "react";
import { Button } from "antd";

import {
    CanvasMediaLightbox,
    CanvasMediaPreviewFrame,
    CanvasPreviewButton,
    CanvasPreviewToolbar,
} from "@/components/canvas/media-preview";

const localImages = [
    { src: "/lighting-presets/rembrandt.png", title: "伦勃朗光" },
    { src: "/lighting-presets/sunset.png", title: "日落" },
    { src: "/lighting-presets/blue-backlight.png", title: "蓝色逆光" },
];

export function LocalMediaBrowserExample() {
    const [open, setOpen] = useState(false);
    const close = () => setOpen(false);

    return (
        <>
            <Button onClick={() => setOpen(true)}>查看图片</Button>
            <CanvasMediaLightbox open={open} title="本地图片预览" onClose={close}>
                <LocalImageBrowser onClose={close} />
            </CanvasMediaLightbox>
        </>
    );
}

function LocalImageBrowser({ onClose }: { onClose: () => void }) {
    const [index, setIndex] = useState(0);
    const [size, setSize] = useState({ width: 1, height: 1 });
    const image = localImages[index];

    return (
        <CanvasMediaPreviewFrame
            width={size.width}
            height={size.height}
            label={image.title}
            onClose={onClose}
            onPrevious={index > 0 ? () => setIndex(index - 1) : undefined}
            onNext={index < localImages.length - 1 ? () => setIndex(index + 1) : undefined}
            toolbar={
                <CanvasPreviewToolbar label="图片浏览操作">
                    <span className="px-1 text-[var(--fs-label)]">{image.title}</span>
                    <span className="px-1 text-[var(--fs-label)] tabular-nums">
                        {index + 1} / {localImages.length}
                    </span>
                    <CanvasPreviewButton label="结束预览" onClick={onClose}>
                        完成
                    </CanvasPreviewButton>
                </CanvasPreviewToolbar>
            }
        >
            <img
                key={image.src}
                src={image.src}
                alt={image.title}
                className="block size-full object-contain"
                draggable={false}
                onLoad={(event) => {
                    const element = event.currentTarget;
                    setSize({ width: element.naturalWidth, height: element.naturalHeight });
                }}
            />
        </CanvasMediaPreviewFrame>
    );
}
~~~

Frame 的 width/height 应取真实自然尺寸或调用方明确提供的媒体比例；不要把生成请求分辨率当成参考素材的真实尺寸。初次加载未知时，示例使用 1:1 临时比例，图片加载后以自然尺寸更新。

### 历史结果的业务接法

[CanvasVersionCompareModal](../src/components/canvas/canvas-version-compare-modal.tsx) 是四个通用组件的现有业务使用方：在内部保存所选 ID，从版本数组派生当前页、首末状态及媒体尺寸，再通过 CanvasMediaVersionPreview 提供内容。不要在通用 Frame 或按钮里增加“版本主节点”逻辑。

| 业务输入/回调 | 约定 |
| --- | --- |
| versions | 已按当前节点归档/版本族规则整理的真实 CanvasNodeData 数组。 |
| onSetPrimary(nodeId) | 同步返回 boolean；true 表示已完成节点更新并关闭预览，false 保留预览和原错误提示。 |
| onFocus(nodeId) | 定位真实节点；归档项使用 versionStackOwnerId，不能定位隐藏的快照。 |
| 当前版本 | 不重复使用。恢复后所选快照若从数组去重隐藏，选择、页码及当前标记回到稳定 owner。 |
| 历史预览 | 优先已有图片/封面；无视频封面显示原生首帧，不自动播放或请求转码。需要播放时复用 VideoPlayer。 |

#### 连线效果复用

- `ConnectionPath` 使用必需的 `selected: boolean` 表示直接选中连线，可选的 `related: boolean`（默认 `false`）表示单选节点的直接邻边；悬停由组件内部管理，状态优先级为 `selected > hovered > related > idle`。常态使用中性 `theme.node.text`，主线与端点不透明度为深色 0.16／浅色 0.2；普通悬停为中性 0.56，关联边为青色 0.46，关联边悬停时保留青色并提亮至 0.56，直接选中主线与彩色端点为青色 0.85，保持高于悬停的视觉层级。选中时保留 2px 青色主线与短光梭，不挂载整线模糊层和外晕，整线白芯与端点白芯不透明度为 0。未选中悬停使用 3.5px 轻外晕和 4.5px 模糊层，模糊值 1.2px，不透明度分别保持 0.05 与 0.07；未选中的关联边保留 0.08 整线白芯和 0.18 端点白芯，常态和关联态无常驻光晕。明暗落在各描边自身，镜头交互仅保留主线时不会突然变亮。`CanvasProjectWorldLayers` 分别传递直接选中和关联集合，版本预览显式传入 `selected={false}`。
- 选择回调为必需的 `onSelect(connectionId: string): void`，可选右键回调为 `onContextMenu(event, connectionId): void`，由组件传入当前连线 ID。`ConnectionPath` 使用标准 `React.memo(ConnectionPathView)` 的完整 props 浅比较，调用方直接传入稳定处理器；不再维护手写属性比较器或为每条线包装独立回调。
- `CanvasConnectionShuttle({ pathD: string, color: string })` 输出 SVG 子 `g`，须放在继承 `--canvas-wire-inverse-scale` 的现有连接 SVG 层中。`ConnectionPath` 已在 `showVisual && selected && !denseReadonlyWire` 时自动挂载，作为选中态局部强调替代整线常驻发光，取消选中即卸载；普通悬停、节点关联与只读 dense 不挂载。亮段长 36 个屏幕 CSS 像素、速度 95px/s、亮芯宽 1.8px，两端渐变透明，完全离开终点后空档 0.35s（33.25px 行程）再循环；亮芯外叠加同一短段的 3.6px 窄柔光，不透明度 0.26、模糊值 0.9px。当前深色主题使用近白色、浅色主题使用深青色，灰／青状态规则保留。
- 短光梭的 `pathD` 保留整条连线，亮芯与窄柔光共用同一 36px 单段 dash 和局部渐变；组件读取实际 DOM 路径的 `getTotalLength()`／`getPointAtLength()`，沿真实弧长移动并定位局部渐变，每帧读取实时逆倍率补偿长度、速度、描边与模糊。世界几何预览继续更新路径与端点，不再覆盖渐变坐标；group 统一控制显隐，可见亮段不透明度为 0.95，空档或暂停时为 0。挂载期间仅用一个 RAF，不逐帧写 React 状态；标签页隐藏、视口平移／缩放交互、减少动态效果或任一祖先 `.no-motion` 时暂停并隐藏，条件解除后恢复，卸载时清理 RAF、属性观察器和事件监听。
- [`canvas-connection-cable.ts`](../src/lib/canvas/canvas-connection-cable.ts)（`@/lib/canvas/canvas-connection-cable`）提供 `connectionColor(light = false)` 作为连线强调态、Leafer 电弧与冲击波共用的青色：深色主题使用 `#77d9de`，浅色主题使用 `#388d93` 调整对比度，不接收 seed 或按连接分配四色；常态 SVG 连线由组件使用中性主题色。模块还提供 `cablePath` 共享几何，以及 `createCableMotion`／`advanceCableMotion` 控制点弹簧状态；端点实时跟随，`moving` 为 `false` 时可停止推进，模块不自行调度帧。`cableImpactContour(point, bounds, padding)` 返回同一接入口出发的正反圆角轮廓、周长及 `pointAt(distance, reverse?)`，按真实圆角弧长为冲击波光斑（light）和尾迹（wake）采样位置；`CableImpactBounds` 的位置、宽高与圆角均为世界坐标。
- 同模块导出固定尺寸常量 `cableStroke`，供普通已连接 SVG 连线与 Leafer 临时拖线复用：主线 2px、端点 4px、衬底 3px、白芯 0.43px、端点白芯 1px。Leafer 临时拖线沿用 `halo = 4.5`；SVG 悬停单独使用 `hoverHalo = 3.5`，模糊层为 `emphasisHalo = 4.5`、`emphasisBlur = 1.2`，收窄悬停不影响拖线。数值均为固定屏幕 CSS 像素，由各绘制层按实时倍率补偿；只读 dense 连线保留原有尺寸，不应用此组常量。16px 透明连线命中范围独立于可见线宽。
- 可见 SVG 描边仅对 `stroke` 与 `stroke-opacity` 使用 `160ms * var(--motion-scale)` 的 `ease-out` 过渡，不过渡路径或几何；透明命中路径不参与过渡。屏幕线宽补偿、16px 命中与只读 dense 低对比虚线保持原有边界。
- 同模块导出 `connectionHandleDiameter = 20`，仅表示加号圆钮包含描边的固定屏幕 CSS 外径，由加号绘制与定位层复用；接入口提示圈与扩散圈按目标节点的世界尺寸绘制。
- 同模块导出 `connectionImpactDuration = 560`（毫秒）与 `cableImpactOffset(elapsed, width, side)`，由外部时钟采样世界坐标位移。幅度为节点宽度的 2%，水平按接入侧镜像，纵向为未镜像采样幅度的 -0.225 倍；时间节点为 `[0, 0.22, 0.7, 1]`，幅度为 `[0, 1, -0.15, 0]`。复用 Motion `interpolate`，分段使用 `easeOut`、`cubicBezier(0.6, 0, 0.7, 1)`、`easeInOut`，在峰顶以零导数进入回程；节点自身不播放缩放或三维变换，世界镜头自然缩放位移。
- [`canvas-connection-port-effect.ts`](../src/lib/canvas/canvas-connection-port-effect.ts)（`@/lib/canvas/canvas-connection-port-effect`）导出 `CanvasPortEffectStyle = "wave" | "breath" | "haze" | "edge"`、`canvasPortEffectOptions` 与 `CanvasConnectionPortEffect`。四款分别为「细光波外扩」「边缘呼吸」「柔光晕扩散」「沿边聚光」；选项名称与说明由同一数组提供。绘制器通过 `new CanvasConnectionPortEffect(parent)` 挂入既有 Leafer group，`draw(input)` 接收接点坐标、节点宽度、接入侧、颜色、风格、毫秒时间及成功／减少动态效果状态，`hide()` 隐藏；不创建 RAF，随所属 group 销毁。外围仅使用空心 `Path` 描边与模糊，小中心点为唯一填充图形。
- [`canvas-connection-cable-scene.ts`](../src/lib/canvas/canvas-connection-cable-scene.ts) 的 `CanvasConnectionCableScene` 是非 React 临时绘制器，复用现有 Leafer world 与 DPR。`CanvasCableDraft.target` 为 `CablePoint & { nodeWidth: number }`，位置与目标节点宽度均使用世界坐标；单线、反向与批量草稿均须传入真实目标宽度。接点基础尺度 `D = nodeWidth * 0.09`，四款外围图形按各自曲线绘制，中心点直径 `0.24D`；全部随世界镜头同比缩放。靠近时中心点使用 `input.ink`，深色主题为白点、浅色主题为深点，成功时使用主题青色。`CanvasLeaferGraphicsLayer` 的必需 `connectionPortEffect` 传给 `sync(inputs, scale, reducedMotion, effectStyle)` 的第四参数，靠近与成功实时使用同一风格；离开接点后隐藏并清除靠近计时，切换目标或风格重新起算。单线传递 `connectionTargetHandleId`，批量传递 `targetHandleId`，保留分镜等多端口的准确位置。
- `CanvasConnectionCableScene.hasContent` 是只读 getter，有活动草稿、松手释放过渡或成功反馈时返回 `true`。镜头预览期间，`CanvasLeaferGraphicsLayer` 据此同步小覆盖层的视口、强制绘制并重置合成预览，实时提交几何与反馈；接点材质与中心点随世界镜头缩放，原连线与沿边亮带的屏幕描边继续按实时倍率补偿。空闲时继续使用原 CSS 合成预览。
- `new CanvasConnectionCableScene(parent, host, render, onFeedbackNodesChange)` 复用现有 Leafer world，必需 `render: () => void` 同步提交覆盖层，当前使用 `leafer.forceRender(undefined, true)`。必需的 `onFeedbackNodesChange(nodeIds: ReadonlySet<string>)` 仅在释放与撞框反馈目标的并集变化时调用；页面将集合并入既有 `lodPinnedNodeIds`，保留目标真实 DOM 至释放／撞击结束，不逐帧写 React 状态。`CanvasLeaferGraphicsLayer` 的 `projectId` 变化时重建场景、清理旧集合并重置交互及连接引用；`onConnectionFeedbackNodesChange` 负责向页面传递集合。
- `release(trackId, targetNodeId, point, color, bounds, prepareFeedback): boolean` 只接管真实新增连接对应的已绘制草稿，必须先于 `sync` 清空草稿调用；`prepareFeedback` 为 `() => CanvasConnectionImpactFeedback | null`，延迟到接触端口时执行。接管最后实绘线头与控制点，以 60ms 快速吸附到各自端口，曲线控制点同时过渡到与正式 SVG 一致的默认 `scale = 1` 几何；到达端口的同一 RAF 才准备并开始撞框。接触后保亮 120ms，再用 100ms 淡交正式线；60ms 是本项目的过渡设计。批量先接管全部条目再同步草稿，同一目标共用撞击时钟，各条线保留各自 handle 接点。返回 `false` 表示没有可接管草稿，已确认的合法新增可直接调用 `flash`，不伪造释放轨迹；连接数据本身仍即时提交。
- `CanvasConnectionCableScene.flash(targetNodeId, point, color, bounds, feedback)` 增加必需首参目标节点 ID，`feedback` 为准备函数返回的会话或 `null`；仅用于真实新增连接。场景用同一 RAF、同一 `elapsed` 更新节点 DOM、关联 SVG、释放线、接点材质与沿边波；同一目标的新会话替换旧反馈。四款成功接点材质在 650ms 内淡出，整节点回弹保持宽度 2%／560ms，沿边波保持 650ms、屏幕亮头 2.2px、24ms 亮起阶段。直接 `flash` 从首个 RAF 起算，经 `release` 接入时从接触端口的同帧起算；同步视口或倍率保留已排队帧。`cancelImpacts()` 清理释放线和成功反馈，归还节点根层、SVG 几何及 LOD 保留集合；指针按下、新接线、真实拖动、场景销毁、减少动态效果或无动效模式均沿用此清理边界。取消、非法、重复连接及初始加载不触发成功反馈。
- 普通 `CanvasNode` shell 复用 `::after` 绘制固定屏幕宽度的细灰描边，按常态、悬停、选中与连接接收状态分级；composer、director 和 dense 节点保留各自的边框处理边界。
- [`useCanvasConnectionFeedback(surfaceRef, tilt, connectionActive)`](../src/components/canvas/use-canvas-connection-feedback.ts)（`@/components/canvas/use-canvas-connection-feedback`）只负责拖线目标倾斜与移出回弹；`surfaceRef` 指向标题与卡片共用的反馈层，`tilt` 为当前目标倾斜数据或 `undefined`，必需的 `connectionActive` 表示当前是否仍在接线。完成、取消或准备成功反馈时，立即停止原 Motion 动画，重置并解绑运动轴及透视，同步清除 DOM 变换和反馈标记。调用方生成 `tilt` 时也须以 `connectionActive` 为条件；hook 不再单独播放成功动画或创建 RAF。
- 同模块导出 `prepareCanvasConnectionImpact(container: HTMLElement, nodeId: string): CanvasConnectionImpactFeedback | null`，同步清除目标拖线倾斜并准备整节点预览会话；容器或目标不可用时返回 `null`。释放过渡将此调用封装为函数传给 `release`，到达端口才执行；没有已绘草稿的直接成功反馈将返回值交给 `flash`。成功位移、SVG 与光波统一由场景推进。
- [`canvas-live-viewport.ts`](../src/lib/canvas/canvas-live-viewport.ts)（`@/lib/canvas/canvas-live-viewport`）提供专用 `beginCanvasConnectionImpactPreview(container, nodeId)`、`getCanvasConnectionImpactPreview(container)` 与 `subscribeCanvasConnectionImpactPreview(container, listener)`。`CanvasConnectionImpactPreview` 为节点 ID 到世界坐标偏移的只读 Map；`CanvasConnectionImpactFeedback` 包含 `nodeId`、`update(offset): boolean`、`finish(): void`。`update` 同步写整个节点根层的 `style.translate` 并通知 SVG，目标卸载、会话被替换或无动效时返回 `false`；`finish` 只清理当前会话仍拥有的 translate，避免旧会话覆盖新反馈或真实拖动，订阅函数返回解除订阅函数。
- `CanvasProjectWorldLayers` 将成功偏移 Map 与既有拖动预览组合，复用原 SVG 几何刷新，让节点入线、出线、端点、透明命中路径及悬停新挂载描边同帧跟随；自定义 `connection.pathD`、dense 连线继续按原几何语义处理。覆盖层在 `pointerdown` 捕获阶段、拖动预览或新接线开始时调用 `cancelImpacts()`；场景结束、销毁、减少动态效果、`.no-motion` 或节点卸载均清理会话和临时图形。
- [`useCanvasPreferences()`](../src/pages/canvas/use-canvas-preferences.ts) 提供 `connectionPortEffect` 与 `changeConnectionPortEffect(style)`，默认 `wave`，使用 `scopedLocalStorage` 的 `canvas:connection-port-effect` 保存当前账号在本机的选择；不写画布文档或撤销记录。`CanvasToolbar`、`CanvasAppearanceControls` 接收必需的 `connectionPortEffect` 与 `onConnectionPortEffectChange`，复用原外观按钮显示四款和当前说明，切换后可直接在真实拖线与成功接入中对比。
- 连接合法性、命中和持久化继续由原控制器处理，特效层不修改连接规则或加号的 44px 点击区。遵守 reduced-motion 与 `.no-motion`；线身静止且无接点动效、释放过渡或冲击波时停止 RAF。取消与卸载释放临时图形；合法新增后的松手草稿由释放过渡接管，减少动态效果时直接交接正式线。

| 风格值 | 显示名称 | 接点表现 |
| --- | --- | --- |
| `wave` | 细光波外扩 | 细线从接点向外散开，外围中心透空。 |
| `breath` | 边缘呼吸 | 一道薄环轻微呼吸，边缘柔和亮起。 |
| `haze` | 柔光晕扩散 | 环形柔光向外扩散，减弱硬轮廓。 |
| `edge` | 沿边聚光 | 接入边缘上下铺开短光带，不画完整圆圈。 |

真实新增连接确认后，先接管现有草稿，再同步已移除结束草稿的 `nextDrafts`；批量条目全部接管后只同步一次：

```ts
import { prepareCanvasConnectionImpact } from "@/components/canvas/use-canvas-connection-feedback";

const prepareFeedback = () => prepareCanvasConnectionImpact(container, targetId);
const releasing = cables.release(trackId, targetId, point, color, bounds, prepareFeedback);
cables.sync(nextDrafts, viewportScale, reducedMotion, connectionPortEffect);
if (!releasing) {
    cables.flash(targetId, point, color, bounds, prepareFeedback());
}
```

## 新增与维护

- 新 UI 先查本目录，再查现有依赖和源码 Props；已有组件能满足时直接组合。UI 族使用族级 index.ts，不新建一个囊括全部组件的大 barrel。
- 满足两处真实重复或明确交互契约后再抽共享组件，保持组件关注点单一。画布业务状态、资源读写和模型请求留在原适配/业务层；展示组件只接内容和动作。
- 可复用接口应显式说明必填值、回调成功语义、资源来源、主题、关闭销毁及必要 Provider。代码注释与实际 Props 为接口权威，手册只放导入及使用示例，不复制完整实现。
- 新增、删除或移动公开组件时同步更新本表和相应族的 index.ts；只在源码已落地后纳入目录，不登记规划组件。
- 本次目录基于 TSX AST 的公开 JSX 组件导出与人工分类，并额外只读核对 .ts 文件中的 createElement、Context 和转导出。命名导出有多个时计为多个公开组件；族转导出没有重复计数。
- 下列内容有用途但不是本表中的 React 组件：canvas-image-toolbar-tools 的动作构建函数、use* hooks、canvas-node-action-context 的 Context 对象、类型、样式与纯计算工具。需要它们时按原模块直接复用，不为凑组件目录再包一层。

本手册描述的是当前已有代码。组件是否触发资源查询、任务恢复、服务调用或媒体播放，应以其源码和调用方实际配置为准。
