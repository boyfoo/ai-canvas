# 抽离与二开说明

## 来源与范围

来源提交：`b3b6e2e380cb13cead3b7eb0d9c479a0f7125fad`。原仓库保持原样。本工程保留完整 `pages/canvas`、`components/canvas`、`lib/canvas`、`stores/canvas` 和类型定义，按需要调整其中的宿主边界，没有改写拖拽、虚拟化、空间索引或媒体激活策略。

原整站前端先复制到独立目录，再以 AST 引用图和人工核对移出 104 个未被目标工程使用的源码文件。记录见 `extraction-manifest.json`。引用图同时追踪静态导入、动态导入、类型导入和 Worker URL；所有画布功能目录作为保护根。路由与动态资源另外核对，不能仅靠引用数量判断删除安全。

## 已完成的分离

1. 独立入口直接进入 `/canvas`，保留画布编辑及素材、技能、扩展、设置与项目支持路由。
2. `CanvasLayout` 接管高度、浮层标记、主题、操作进度与 `workspace:navigate`，无桌面更新和全站搜索监听。
3. 原生下载改为浏览器下载，ZIP 和大视频导出保留；不再经 Wails 传送 Base64。
4. 参考素材设置与上传迁到 `CanvasHostServices`，深度工具改为处理服务预检。
5. 移除更新前保存注册，保留导演保存协调器及时间线卸载保存。
6. 资源策略显式配置，默认服务资源库，不再凭 loopback URL 判断桌面。
7. 画布事件流使用配置的 API 地址，支持 HTTP(S) 与 Cookie 凭据；浏览器新标签和深层跳转使用 History 路由。
8. 复制原来从后端相对导入的图片／视频模型能力 JSON，并搬入渠道设置使用的应用图标；构建不依赖原仓库目录。
9. 构建配置、声明生成器、第三方许可与全部高级媒体资源放入本工程，移除桌面和精简构建入口。

保留项目支持视图，是因为画布有实际的项目画风、章节与项目画布列表链接；它们按路由懒加载。独立首页、创作门户、Agents 和实验页面不再进入工程。

## 验证

`bun run build` 包含 TypeScript 检查与完整生产打包。`bun run test` 当前覆盖 126 项检查，包括宿主 HTTP 接入、真实失败传递、上传去重与串行、取消信号、资源策略、无原生桥接约束，以及上游画布空间索引、媒体激活、标题交互和导演保存回归。

原工程的全量测试包含桌面、后端目录和产品门户假设，未整套带入；完整原测试仍可在未修改的上游源码查阅。这里保留与本次风险直接相关的测试，并继续添加独立工程的回归。

不把生产构建或测试接口数据视为付费模型、助手宿主、对象存储、深度服务或真实持久化的验收。浏览器冒烟结果与实际未验能力在交付时单独记录。

`bun run test:browser` 使用独立 Chrome 配置，启动短暂的测试 HTTP 服务读取 `dist`，并提供内存 API 夹具。检查生产画布加载、节点改名与拖动、模型设置、参考存储与深度设置、素材／技能／扩展支持页面。结果和截图写入 `.local/browser-smoke`。未实现的夹具接口返回 404 并记录，相关业务不计入通过范围。

## 继续开发建议

先按 `backend-contract.md` 接通服务，再增加节点和业务功能。节点定义与工具注册延用原有注册体系；大媒体继续使用资源引用和对象 URL 生命周期，不塞进 Zustand 或 localStorage。

当前保持依赖版本和画布算法，便于与上游对照。未为此次抽离额外升级 React、替换渲染引擎或重新设计节点，以减少行为差异。
